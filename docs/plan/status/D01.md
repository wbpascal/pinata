## Findings so far (read in the code)

- **Process**: "DataServer" (`DataServerInfo_Account.txt`). Packets are queued to N *session workers*
  (`FUN_00406010`); each worker opens its own ODBC connection (`FUN_00405f20` → `FUN_00419bb0`, object at worker+0x124c)
  and runs the parser. Handlers get `this` = worker context, `*(this)+0x124c` = the worker's DB object, `this+4` = session.
- Sends: `FUN_004055a0(session, CSendPacket)` (CSendPacket: `FUN_004121d0` init, `FUN_00412310(buf, op, size, src)`, payload
  at +5; `FUN_004121f0` uses `{len}` for size+2 < 0x100 else `{0, u16 len}`), or `FUN_004055d0(session, rawFrame, size)` raw.
- **CheckAlive** `FUN_004046c0`: returns 0 and logs "접속 미인증 상태에서 패킷 도착…" (packet before authentication) when
  session byte +0xdc == 0, else 1 (confirmed in asm at 0x40471e / 0x404735).
- `FUN_00402510` = `return CheckAlive()`: 0x0823, 0x0C10 NC_USER_LOGIN_DB, 0x0C11 NC_USER_LOGOUT_DB, 0x140D, 0x140E are
  **no-ops** in Account (only CheckAlive).
- CPFs: 0x0801/0x0805 `return 1`. 0x0802 `FUN_00404830`: payload {u8 echo @2, u8 server_id_to @3, u8 from @4, u8 world @5,
  u8 zone @6, u16 key @7}; rejects (close) if session already connected (state +0xdc not 0/2 and type+0xe0 != 3),
  if `to != my_type` (`DAT_0044b808`), or `key != to + from`; else stores type/world/zone at +0xe0/+0xe4/+0xe8, sends
  0x0803 {u8 echo, u16 0}, state=1, connect time at +0xec. 0x0803 `FUN_00404ce0`: if u16 @3 == 0 → state=1.
  0x2801 → 0x2802 {u8 echo, u8 my_type, u16 n, n×7 B {type, world, zone, u32 packed time}}; 0x2803 → 0x2804 {u16 0x0600},
  `_DAT_00654bbc = 1` (stop); 0x2805 → 0x2806 {echo, my_type, u16 0}; 0x2807 → 0x2808 (0xaa B, link counts per
  type/world/zone; type > 20 counted as 10, world/zone > 1 as 0). Same code as Login/Zone OPTool handlers.
- **0x0C07 / 0x0C39 / 0x0C53 (PASSWORD_CHECK_REQ, GER, CH)**, identical bodies `FUN_004039c0 / 00403b20 / 00403c80`:
  REQ = {u16 handle, char user[256], Name4 password(16 B)}; calls `usp_User_loginGame(6)` via `FUN_00418dd0(user, pw,
  &authid, &block, &loginable)` → returns userNo. Reply raw 0x0C08 / 0x0C3A / 0x0C54 (PDB `PROTO_NC_USER_PASSWORD_CHECK_ACK`,
  0x11f B): {handle, id[256], password[16] (zero unless userNo == -1, then echoed), u32 usrregnum, u8 authid, u32 block,
  u32 loginable}. **(original bug)** raw frame length byte is `0x21` = (u8)0x121 while 0x122 bytes are sent: length
  truncated, Login mis-frames the reply (the PDB `_SEND` struct has `uchar size`, so the original design cannot hold it).
- **0x0C5B US_PASSWORD_CHECK_REQ** `FUN_00402fe0` (the live login path): reply 0x0C5C (CSendPacket, 0x161 B, PDB
  `PROTO_NC_USER_US_PASSWORD_CHECK_ACK`): nError starts 0x41 (OK), nUserNo = -1; copies sUserName (256 of 260), sPassword
