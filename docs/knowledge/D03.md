# D03 knowledge: Character server items, economy, pets, house

Facts other items need. Details: `docs/pseudocode/db/D03-character-items.md`. Names: `tools/protocol-re/names/character/D03.json`
(all 123 decompiled handlers `fc_NC_*`, item helpers). Layouts: `docs/protocol/annotations/D03.json` (35, key `character`).

## Persistence model (for Z04, Z05, D06, X01)

- An item = one `tItem` row `{nItemKey, nOwner, nStorageType, nStorage, nItemID, nFlags}` + one `tItemOptions` row per attribute
  field. Option type = class base + field index (BYTELOT 1, WORDLOT 2, DWRDLOT 3, AMOUNT 4, QUESTITEM 300, AMULET 400…, WEAPON 500…,
  ARMOR 600…, SHIELD 700…, BOOT 800…, FURNITURE 900…, DECORATION 1000…, BINDITEM 1100…, ITEMCHEST 1400…, HOUSESKIN 1500,
  RIDING 1600…, COSWEAPON 1800, COSSHIELD 1850, ACTIONITEM 1900, CAPSULE 2100…, CLOSEDCARD 2200…, OPENCARD 2300…, NOEFFECT 2500,
  PUP 2700, BRACELET 2800…). Table: §1.3. Save = `ItemAttr_Save` FUN_0046a730, load = `CGameDB_Item::GetItemOptions` FUN_004681a0.
  Weapon licence kills, weapon titles, gem sockets (`tItemEnchant`) and pet name/mind/stress live in separate tables.
- Storage types seen: 0 guild-academy reward box (owner = guild), 2 reward box, 4 guild storage (owner = guild), 6 account
  storage (owner = user number, 36 slots a page), 8 equipped, 9 inventory, 10 chest/capsule contents (hidden), 11 temporary
  during swaps (procedures).
- The Character server trusts the zone for keys, owners (mostly), lots, prices and attributes. Only these check ownership:
  sell, drop, reloc/exchange, merge, split-n-merge, trade, capsule open, upgrade, endurance, belonged cancel.
- No request has a length check; most multi-step requests are not transactional (D03-B3).

## Answers to open questions

- **Z05 §12:** every failure code per request is in the D03 sections (§2–§14); answer layouts match Z05 §2 except the ones listed
  there as raw frames.
- **Z07 §7 (card reward repeat):** `usp_Collection_setReward` refuses an existing `(nCharNo, nReward)` row (−2222 → `0x2BA9`), and
  the reward item created first is deleted again: no duplicate reward on the DB side *(db-backup, w00)*.
- **Z07 §9 (pets):** create `0x3408` ok / `0x3409` / `0x3400` (pet no −1); load `0x3420` / `0x3421`; rename `0x3418` / `0x3419`;
  remove `0x3428` / `0x3429`. Pet number −1 in load/rename/remove → no answer (D03-B24). Procedures have no source (D06).
- **0xC411 2016 body:** `{u32 regnum, u16 handle, u16 RewardID, u64 itemKey, u16 itemId, attr}` (0x77); the item goes to the reward
  box (type 2, free slot).
- **0xAC2C:** the body is `NC_DICE_TAISAI_DB_ITEM_ID_CHANGE_REQ` (PDB enum gives cmd 44 to both it and `…TIMER_CMD`), answered with
  `0xAC2D`.
- **0x34CF:** body `{u32 charNo}` = 2017 `NC_ITEMDB_RESET_SCROLL_LINK_MAP_INFO_CMD`; clears the link-scroll destination, no answer.
- **0x345D QUESTITEMGET:** unimplemented stub ("work in progress" log), no answer.
- **0x3437 MOB_DROP_CMD:** no DB write, no log, no answer.

## For other items

- **D04:** quest reward 0x345B calls `SetCharTitles` FUN_0046d3e0 (`p_Char_SetTitle`, log text "fc_NC_CT_DB_SET_CMD"); every cen
  purchase credits 10 % to the holy-promise upper member (`usp_HolyPromise_setMoney(charNo, price/10, levelGap 10)`).
- **D05:** GameLog packets sent here: 0x043F, 0x0439/0x043A, 0x0445–0x0449, 0x044A, 0x044C, 0x044F, 0x0453, 0x0456, 0x0457, 0x0459,
  0x045A, 0x045B/0x045C, 0x045D, 0x045E/0x045F, 0x0460/0x0461, 0x0462, 0x04AA, 0x04BE, 0x0518–0x051F, 0x0554, 0x079A/0x079B,
  0x079C, 0x079E/0x079F, 0x07E8, 0x07F2, 0x07F8, 0x07FD, 0xC80D, 0xC80E, 0xC814, 0xC815. Several item logs carry the literal map name
  "Need" (D03-B11).
- **D06:** procedures without source: `usp_Pet_getInfo/setCreate/setDelete/setName/setTendency`, `usp_LinkScroll_SetDestMap`
  (charNo, char[13], out), `p_Item_MiniHouse_Effect_Resource_Del` (6), `p_MiniHouseURL_Get/Set` (userNo, url).
- **W04 / D04:** 0x34BF friend-point items send `0x541C {1, {charNo, points left, 0}}` to the WM.
- **Z06:** trade answers go to both partners (`0x343D` SUC / `0x343C` FAIL `{hdr, lock, err}` with 0x84A–0x850); booth answers
  `0x3456` once with type 1/2/3 (buy booth) or 4/5/6 (sell booth); booth codes 0xA44, 0xA4A, 0xA4E, 0xA4F, 0xA50, 0xA52, 0xA63.
- **Z13 / Z07:** mini-house gates `tMinihouseGate` (bType 0 permanent, 1 timed; scroll item deleted by `usp_Minihouse_setGate`);
  visitor count is incremented for the character number the zone sends.
- **Startup state:** `CollectionCardSerial` is loaded only by `0xC414`; before it arrives sealed cards are saved without
  serial/options.

## For capture scenarios (X02)

Claims that only traffic or the database can settle (doc: `docs/pseudocode/db/D03-character-items.md`). The D03 packets travel
Zone ↔ Character server (`PG_W00_CDB`, port **9411** in `9Data/ServerInfo/ServerInfo.txt`), so the capture filter of
`capture-guide.md` must be widened (`… or tcp port 9411`, loopback when all servers run on one PC). Whether that link is
encrypted was not checked. Most claims are best checked with a SQL look at `tItem` / `tItemOptions` before and after the action
(`SELECT * FROM tItem WHERE nOwner = <charNo or userNo>`, `SELECT * FROM tItemOptions WHERE nItemKey = <key>`).
