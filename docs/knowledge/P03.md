# P03: Wireshark dissector (`tools/wireshark/fiesta.lua`)

A Lua plugin that decodes Fiesta client↔server traffic live in Wireshark. It is **generated** by
`tools/protocol-re/make_dissector.py` (last step of `tools/protocol-re/regen.sh`) from the same docs the
capture decoder uses (`pcap_decode.load_docs`), so it picks up every new name and annotation. Do not edit
`fiesta.lua` by hand: the Lua logic lives as a template string in `make_dissector.py`.

## Install and use

See `docs/plan/capture-guide.md` § "Live decoding in Wireshark". In short: copy `fiesta.lua` to
`%APPDATA%\Wireshark\plugins\`, restart or Ctrl+Shift+L, filter `fiesta`. Preferences under *Protocols → FIESTA*:
login / WM / zone port lists (defaults = `ServerInfo.txt` type-20 rows: 9010, 9110, 9210/9212/9214/9216) and
*Show password*.

## Fields

| Filter field | Meaning |
|---|---|
| `fiesta.server` | `login`, `wm` or `zone`, from the port preference |
| `fiesta.dir` | `C->S` or `S->C` (client side = the port not in the port lists) |
| `fiesta.len` | length prefix value (opcode + payload) |
| `fiesta.opcode`, `fiesta.dept`, `fiesta.cmd` | opcode, `op >> 10`, `op & 0x3FF` |
| `fiesta.name` | `opcodes.json` name, else the annotation's name. The item text adds the annotation name in `[…]` when it differs |
| `fiesta.xor_index` | XOR-499 start index used for this client body |
| `fiesta.layout` | `annotation` (verified) or `generated` (`layouts.json`) |
| `fiesta.payload` | payload bytes; decoded fields are text items below it |

Expert info: `fiesta.unknown_opcode` (no name, annotation or layout), `fiesta.size_mismatch` (annotation end ≠
payload length, a field runs past the payload, no S→C send site with this size, or a C→S handler length check),
`fiesta.no_seed` (client packet before any `0x0807` on that connection).

## How it decodes

- **Framing:** `dissect_tcp_pdus` with min header 3 (every PDU is ≥ 3 bytes) and README §1.1 lengths
  (`len:u8`, or `00 len:u16`). Wireshark's TCP reassembly handles PDUs split across segments.
- **Decryption:** C→S bodies only. Per connection (server addr:port + client addr:port), an S→C `0x0807` sets
  the index to `seed % 499`; each C→S body uses the current index and advances it by its length. This runs
  only on the first pass (`not pinfo.visited`, which is in frame order); the start index is cached per
  `frame number : tvb raw offset`, so later re-dissection in any order gives the same result. `proto.init`
  resets the state on reload. Decrypted bytes go to a new data source tab "Decrypted".
- **Fields,** same rules as P01 (`docs/knowledge/P01.md` §5): annotations (`annotations.json` +
  `annotations/*.json`) first, with structs and count-referencing arrays; else the generated C→S layout of the
  client parser class; else the S→C send site whose size equals the payload (else a variable-size site, else
  the first site + size expert). Fields named `error`/`reason` are resolved with `client-error-codes.json`.
- **Password:** annotation fields whose name contains `password` show `********` and are overwritten with
  `*` in the Decrypted tab unless *Show password* is set. The encrypted bytes in the frame are unchanged.
- No bit operators and no `%d`/`%X` on large values: runs on Lua 5.2 (Wireshark ≤ 4.2) and 5.4 (4.4+).

## Tested

`python3 make_dissector.py --selftest` (needs `pip install lupa`, not part of `regen.sh`) loads the generated
file in Lua 5.2 and 5.4: XOR table, decrypt, seed tracking, annotation decode (struct array, password mask,
show-password), size and unknown-opcode issues; then runs the Wireshark glue through a small mock of the
Lua API with a login stream (seed, encrypted `0x0C65`, long-form `0x0C5A` + `0x0804` in one segment, world list,
unknown opcode), a WM generated-layout size mismatch and a zone pre-seed `0x0806`; re-dissection in reverse
order must give identical trees, and the password must not appear anywhere. **Not yet tested in a real
Wireshark**: the mock does not prove the Wireshark API calls; the user must confirm on the capture PC.

## Limits

- No resync: a capture that starts in the middle of a connection may mis-frame (Wireshark then shows garbage
  lengths) and never decrypts (no seed). P01's `pcap_decode.py` handles both offline (sync search, brute-forced index).
- The zone's `0x0806` is sent before the seed, so it is never decrypted (its start index is unknown, P01 §Limits).
- Connection identity is addresses + ports: a reused client port in one capture continues the old state.
- S→C constant checks and "undocumented nonzero" coverage from P01's report are not shown.
