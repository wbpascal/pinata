## Loading facts

- `idb_Load` FUN_00649780 runs once, in `zs_start_home`; nothing reloads it (`&reloaddata` cannot, Z11 §8.6). §8.
- It reads **eight** files: ItemInfo, ItemInfoServer, GradeItemOption, ItemDropLog, ItemSort, ItemInvenDel (through the
  folded reader named `BinaryDataBox<CollectCardMobGroup>` FUN_00648d50), ItemMoney, and WeaponAttrib (read inline,
  not kept). §2.
- Joins: ItemInfo ↔ ItemInfoServer by **file position** (fatal if IDs or row counts differ); GradeItemOption,
  ItemInvenDel, ItemMoney by **InxName** through `idb_btree` (duplicate InxName: the later ID wins); ItemDropLog by ID
  (first match); ItemSort by the string `ItemInfoServer.ItemSort_Index` (fatal if missing); WeaponAttrib by
  `ItemInfo.WeaponType` for every item of that type. §3.
- `idb_MakeSpecialID` exists only as an inlined name (its fatal text); unknown special names stop the zone. §3.7.
- Accessors: `operator[]` FUN_00419020 (null for out-of-range / missing IDs; logs and returns null on a row-ID mismatch, unreachable),
  `idb_2itemid` FUN_00418ff0 (InxName → ID, 0xFFFF if unknown), `idb_SpecialItems` FUN_00418fe0. §5.
- 2016 data passes every fatal check; 13 `sii_*` members are never read; `AttackAngle` is never read; the HP/SP potion
  slot rotation (HP0←HPMPotion1, HP1←2, HP2←0, HP3←3, same SP) has no effect. §7.
- `HitTimeArray` is left uninitialised for items whose `WeaponType` has no WeaponAttrib row: in 2016 only the four
  production tools (Z27-B1, §7.3).
- `sp_ItemInvenDelete` FUN_0051c590 (at map login) sends one `0x3459 NC_ITEMDB_DESTROY_REQ` for all inventory items with
  `eDelConditionType == DCT_LINKIN_ALL` (the 19 ItemInvenDel items). §7.2.
  The packet's count byte is written as 0 (bit 7 "rewrite one item" = 0) and buffer bytes 0x0b–0x18 (payload
  0x09–0x16) are never written; the keys start at buffer +0x19 (payload +0x17).
- Dual swords / claws (`HitTimeArray` slot 0 = 1 ‰) deal no damage on a swing faster than 1000 ms: the tick loop breaks
  at slot 0 (Z27-B7, §7.3).
- `SHND::CommonData<CollectCardMobGroup>` (ctor FUN_00629700, `cd_Load` FUN_005b7b10 from `zs_start_long`, `cd_Find`
  FUN_00627ed0) is documented in §2; the other card tables and `g_CardCollectMake` are follow-up Z28.
