# Z04 knowledge: zone items, inventory, equipment (facts for other items)

Pseudocode: [`docs/pseudocode/zone/Z04-items.md`](../pseudocode/zone/Z04-items.md). Names: `tools/protocol-re/names/zone/Z04.json`
(56). Layouts: `docs/protocol/annotations/Z04.json` (82 packets: all 52 requests, their error ACKs, a few zone→DB requests).

## 1. Inventory model (for Z05, Z06, Z07, D03)

- **Cell address** `ITEM_INVEN = type << 10 | slot`. Boxes: 0 guild-academy reward storage, 2 reward inventory (`p+0x28760`),
  3/13/14/16 mini-house boxes (`p.vt[0x50](type, &box)`, result 0x1181 = OK), 4 guild storage, 6 account storage (`p+0x18258`),
  8 equipment (`p+0x7fd8`, slot = `ItemEquipEnum`), 9 inventory (`p+0x8e2c`), 15 small-item box (`p+0xf758`).
- **Item cell**: `+0 u64 key, +8 u16 itemID (0xFFFF empty), +0xa attribute…, +0x70 ItemAttributeClass*`. Attribute class per
  `ItemClassEnum` via `FUN_0063e2a0(&g_ItemAttrCls, id)`; vt 0x18 IsLot, 0x1c GetLot, 0x20 SetLot, 0x28 class, 0xa4 bound, 0xa8 SetBound.
  Upgrade level / failure counter: weapon/armor/shield/boot attr `+0xa`/`+0xc` of the cell, amulet/bracelet `+0x12`/`+0x14`.
  Gem sockets: `cell+0x3a` 3 × `{u16 gem, u8 rest}`, `cell+0x43` count.
- **ItemInfo offsets** in 2016 equal the 2017 PDB struct (`Class 0x66, MaxLot 0x6a, TwoHand 0x7a, DemandLv 0x7f, Grade 0x83,
  UseClass 0xcf, SellPrice 0xd7, BuyDemandLv 0xdb, WeaponType 0xe8, UpLimit 0xf0, UpSucRatio 0xf3, UpLuckRatio 0xf5, BT_Inx 0x112,
  ItemFunc 0x176`). `g_ItemData[id]` = `{ItemInfo row, ItemInfoServer row, …, [7] ItemSort?, [9] ItemMoney row}`.
- **BelongTypeInfo** rows (`g_BelongType` DAT_150ba8b8) gate drop/sell/trade/store/delete (§1.3 of the pseudocode).
- **New item keys** are built on the zone: `ItemKey_Make(&key, id, kind, zoneNo, worldNo)` FUN_00640710.

## 2. Locking / DB hand-off (for Z05)

`InventoryLocking` (`p+0xfaa8`, vt 0x7d4) holds per-request reservations under a lock index (`p+0xfaac`). Slots used: 0x08/0x0c locked?,
0x10 any lock open, 0x28 release, 0x2c cell lock, 0x30 clear-cell, 0x40 move/replace, 0x48 money, 0x4c fame, 0x50 equip/unequip,
0x54 equip location, 0x58 item-use releaser (carries the `UseEffect` actor), 0x5c soul stones, 0x64 reserved totals, 0x70 coin,
0x7c guild-academy box. The DB request carries the lock index; Z05's ACK handlers apply or release the reservation.
The zone sends **every** item change as a request and waits; nothing changes in memory before the DB answer (except: EQUIP binds
the item at once, `p+0x173cc` "equip in flight" flag, split pending `p+0x1ea8`, upgrade outcome stored in `p+0x2928d…`).

## 3. Item use (for Z03, Z07, Z08)

- `NC_ITEM_USE_REQ` → `g_ItemUseTable[itemid]` (DAT_132879e0, 16-byte entries) → `UseEffect::*` actor (38 classes, table in §6.3):
  `uib_CanUseItem` (code 0x700 ok), `uib_DirectUse` (immediate), else a cast using the item's use skill (`p+0x1d84` cast block with
  `+0x1da4` item info, `+0x1da8` slot); `uib_AfterCast` consumes the item (DB 0x343E/0x343F) and the `InvenCellReleaser_ItemUse`
  calls `uib_Effect` after the DB confirms. **Z03's open question** "`UseItemNormal::uib_AfterCast` success → `so_ply_SkillEraseItemUseSuccess`":
  it is `UseItemSkillErase::uib_Effect` (FUN_0059a1c0) that runs after the DB answer, not AfterCast itself.
- **Megaphone (Z02 open question):** `UseItemRoar::uib_Effect` → `so_ply_RoarItemUseSuccess` (FUN_00540800) → AnnounceData row 11
  `"%s:%s"` → `0x6401 NC_ANNOUNCE_Z2W_CMD` to the WM (world-wide), then `0x204C NC_ACT_ROAR_ACK {0x700}`. Stale queue entry → nothing sent.
- Revive item (`0x3039`): consumed through `UseItemNormal::uib_AfterCast` with actor DAT_132878ec; errors go out as 0x483A / 0x482B.

## 5. Quirks worth knowing

- Several error replies use another opcode: SELL without NPC → `0x3004`, REPURCHASE level → `0x3004`, OPENSTORAGEPAGE → `0x3007`,
  DROP with menu bits → `0x300C`, revive item → dept 18.
- Error replies of `0x3027`, `0x3030`, `0x3032` leave `cen` as stale `g_buf` bytes; `0x301D`/`0x301F` errors are 2-byte packets while
  the client reads `err` at offset 8.
- UNEQUIP checks the lock of `(8, slotinven)` instead of `(9, slotinven)`.
- ENCHANT_* and RANDOMOPTION_CHANGE_ACCEPT have no mode or global-lock check.
