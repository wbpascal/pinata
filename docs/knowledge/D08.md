## 1. Process layer facts (all four DB servers)

- One `DataServer gServer` (size 0x209a68): Account DAT_0044b308, AccountLog DAT_004461a8, GameLog DAT_0044d188.
  `+0x2098b4 m_bStopMainThread`, `+0x2098b8 m_bActiveMainThread`, `+0x209890 m_bOnStopService` (set at service start,
  never cleared, so the `exit(0)` "SELF STOPPED" branch is dead).
- Threads: IOCP 5 × CPU (Login / WM 2 × CPU), session workers min(10 × CPU + 1, 81) each with its own ODBC link, one
  accept thread (select poll with 0 timeout + 10 ms sleep), one main thread (1 s heartbeat tick, nothing else periodic).
- Sessions: fixed pool of `nMaxAccept` (100 in 2016) `CSession` (0x154) created at start, LIFO reuse; heartbeat 0x0804
  after 30 s silence, close 180 s after that, only for authenticated links (D05-B9).
- Job queue: one 2 MB FIFO `{CSession*, frame}` for all links, any idle worker takes the head; no per-link ordering;
  the IOCP thread sleeps 2 ms and retries when it is full.
- The library classes `CIOCP`, `CSocket_IOCP`, `CPacket`, `CSendPacket`, `CIOBuffer`, `WinService`, `MiniDumper`, `String`,
  `AssertClass`, `cShineLogSystem`, `_DebugMessageNew*`, `CServerInfo` (common part) are identical to the WM build (S02,
  W05). The session layer (`CSocket_Session_Manager`, `CSocket_Session`, thread `CSocket_Acceptor::AcceptThread`,
  `CSession*`, `CSessionWorker*`) exists only in the DB servers.
- Official names for the GameLog / Character copies of the process layer: `tools/protocol-re/names/{gamelog,character}/D08.json`
  (they override D05's / D02's own names in `clean.py` output; `Z19.json` still wins for the `CCsl` / `CServerInfo` ones).

## 2. Linked data classes and the ODBC wrapper (D08 §2)

- The zone's game-data library is linked into the DB servers but unused: `itemdatabox` (no file), `itmattcontainer`
  (never read in Account: all `ItemAttrCls_*` code is dead there), `itemoptiondata`, `rewarddata`, `fprewarddata`,
  `charinvenman`, `g_ItmBelongAttr` are built empty by static constructors. `rndbox` (`RandomBox`, 3.3 MB) is filled at
  start-up (`srand(time)` + shuffles). The Character server uses `itemdatabox` (ItemInfo), `mapdatabox` (MapInfo, only `GetCharBaseData`) and `itmattcontainer` (vtable slots 1, 2, 32, 33; never slot 5 `iac_itemcreate`), §4.5.
- The DB builds stub the zone-table helpers of the item-create code: `RidingInitHungry` returns 100, `RidingInitHP` and
  `WeaponCostumInitCharge` are a folded "return 0" (Account FUN_004017c0 / FUN_004036d0); `EnchantSocketRateData` is null.
- `CItemAuthorityBase` ctor (Account FUN_0042efb0 = zone FUN_00631e50): the three 17 × 17 box-to-box matrices read by the
  zone's `IA_CanInvenReloc` FUN_00632280 are written out in §2.3 (no zone doc had them).
- ODBC wrapper (`Database` / `DBRecord` / `CGameDB_Connect`, DB servers only): ODBC 2 environment with connection pooling
  (`SQL_CP_ONE_PER_DRIVER`), one connection + one statement per session worker, autocommit (no `BeginTran` in
  Account / AccountLog), `DBRecord::fetch` / `operator>>` read columns in order as SLONG / ULONG. Bug D08-B4 (`InitEnv`).

## 3. AccountLog differences (D08 §3)

- `DataServer` is 0x209e20 bytes in AccountLog: `+0x209890 CStatistics m_Statistics` pushes the Account members down by
  0x24, so `m_bOnStopService` +0x2098b4, `m_bStopMainThread` +0x2098d8 (the 0x2803 flag), `m_bActiveMainThread` +0x2098dc;
  `+0x2098e8 cLogSystem m_UK_SysLog` (= D01's DAT_0064fa90).
- Start-up opens the syslog file first (`ls_LogSystemInit`; thread creation failure = silent start failure). The main
  thread's 1 s tick also runs `CStatistics::Process` (0x0809 to the WMs on each minute change).
- Workers: 0x1288 bytes, two ODBC links each (ODBC ids 1 AccountLog + 2 Statistics; both rows required).
- `cLogSystem` / `cLS_Queue` official names for D05 §6.1's helpers (GameLog FUN_0040f6b0 `ls_LogSystemInit`, FUN_0040f250
  `ls_LogSystemProcess`, FUN_0040f1f0 `ls_LogReservation`, FUN_0040edf0 `ls_ValidTimeCheck`, FUN_0040ed70
  `ls_CreateDirectory`, FUN_0040f040 `lsq_Push`) are in `names/gamelog/D08.json`. The writer thread has no stop path
  (`ls_bLogThreadStopOrder` is never set): queued lines are lost at exit.

## 4. Character differences (D08 §4)

- `g_Server` DAT_004e2a68, 0x20a47c bytes: Account layout up to `+0x9838` workers, then the game-data objects
  (+0x209890 DefaultCharacterData `CServerInfo`, six `CDataReader` at +0x209d88 … +0x209ed8, +0x209f18 `cUKItemShop`,
  +0x209f4c Tutorial `CServerInfo`), `+0x20a444 m_bOnStopService`, `+0x20a468 m_bStopMainThread` (0x2803 flag
  DAT_006eced0), `+0x20a46c m_bActiveMainThread`, `+0x20a478 g_GameLogLink`.
- Start: `GameData_Load` returns 1 / 0 (any missing table or unknown item index = start failure −4).
  `OnStart_Service` FUN_004027a0: `cUKItemShop` init first ("FAILED - UK ItemShop Init"), then the Account sequence, then
  the 0xC414 self-job.
- Main thread: each 1 s tick also calls `CSession::ConnectToGameLog` FUN_00401cd0 while `g_GameLogLink` is null (blocking
  connect, S02-B5). The link is marked `m_Connection` 2 / server id 3 at connect; GameLog's 0x0803 sets 1. Any closing
  session with server id 3 clears the pointer (D08-B5).
- Workers: 0x12a8 bytes, one ODBC link (id 10 = w00_Character), parser `CParserCharacter` at +0x138, DB object at
  +0x124c; autocommit (no `BeginTran`). `CSession_Manager::FindSession` FUN_0043dc20 = AccountLog's, used by
  `SendToWorldManager` FUN_00402d80.
- Names: 372 Character functions in `names/character/D08.json` (process layer, data classes, STL, crash-dump helpers).
