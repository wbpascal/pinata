## Not reconstructed / uncertain

- The auto-save period after the first one (every 600 s) is read in the code (`ws_save2DB` re-arms
  `so_SetAutoSaveTime`); two consecutive auto-saves of one map session were not captured (capture-validation §14).
- Experience and other state gained since the last save are lost at a zone kill the same way as position *(inferred,
  capture-validation §23.5)*.
- A client killed outside an exit countdown (no `0x1071`) resets its sockets like the captured server-side reset
  (§23.3 / §23.4): the same zone path (`so_banning` arms Kickout, read in `so_Unmark` @ FUN_00558900); the kill itself
  was captured only during a countdown (§23.7).
- Which of the client's `0x0C18 {0}` and the WM's `0x0C19` the zone handles first in a quit is a race; both orders
  were captured (P02-B35), the code reason for `s24` B is not traced (capture-validation §15).
- `0xD1` from the CharDB on a taken name with the 2016 `p_Char_Rename` and a map login after a real rename are not
  captured (the test DB ran a 2018 procedure; capture-validation §14 "Batch 4").
