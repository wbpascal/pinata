## 1. Guild classes in the WM

- The `CGuild` / `CGuildMember` / `CGuildAcademyMember` `Recv_NC_GUILD_*` members are the client's handlers (shared
  code). The WM calls only these slots: `CGuildServer` 0x2C (NOTIFY_CMD) and 0x4C (ACADEMY_NOTIFY_CMD);
  `CGuildMemberServer` 0x1C (JOIN), 0x20 (VANISH), 0x24 (LEAVE, folded with VANISH), 0x28 (GRADE);
  `CGuildAcademyMemberServer` 0x04 (JOIN), 0x08 (VANISH), 0x0C (LEAVE, folded), 0x30 (`GetIndex` by charNo). All others
  are dead in the WM (W06 §1.2 table: slot, opcode, where the WM sends the opcode).
- Opcodes with a client-side class handler but no 2016 WM or zone send site: 0x741F, 0x742B, 0x742C, 0x742E, 0x743A,
  0x743B, 0x743C, 0x743F, 0x7442, 0x9864, 0x9865, 0x9867.
- `CSocket_IOCP::Send` FUN_004666f0 returns 0 for: size 0, `m_Socket == INVALID_SOCKET`, a chunk > 0x2000 after split
  (impossible), `WriteFile` error other than 0x3E5 (buffers freed); otherwise 1. Every WM "send to CharDB" helper that
  returns the send result is therefore 0 exactly when the CharDB link is down or the write fails.
