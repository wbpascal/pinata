# Z11 knowledge: zone GM ampersand (&) commands

Output: `docs/pseudocode/zone/Z11-gm-commands.md` (§1 system, §2 table of all 169 words, §3–§8 commands, §9 helpers,
bugs Z11-B1…B44, coverage boundary). Facts other items need:

## 1. Command system

- **Entry**: a chat line starting with `&` goes to `sp_AmpersandCommand` FUN_0041a060 → `so_ply_AdminCommand`
  (vt 0x964, FUN_00427a40). Words are case-sensitive; the line is at most 100 characters; up to 12 arguments of 32
  characters (a 32+ character word is not terminated, B2). Splitter = `tokenize` FUN_005921c0 (space-separated,
  `"` quotes, `\` escapes; Z11 §1.2).
- **Table**: `ampcmd` (DAT_0087c770), `List<AmpersandCommandElement>` filled by the `AmpersandCommand` ctor
  FUN_00425b70 through `ac_Store` FUN_0041a310 {word, built-in level, member-function pointer}. 169 words → 154
  distinct handlers (153 `ac_*` functions plus the shared no-op FUN_00402370; 13 Korean CP949 aliases share an English
  word's handler, `&&&` / `&disposition` / `&slotmachine` share the no-op).
- **Levels**: per character `tCharacter.nAdminLevel` → player +0x7fa1, `so_AdministratorLevel` vt 0x4d4. A command runs
  when level ≥ its level (1, 10, 50, 100). `AdminLvSet.shn` (`gAdminLvSet` DAT_13388398, `AmpCmdInit` FUN_00419f50)
  overrides levels 1…100 at start; the 2016 table changes only `scrint`, `templink` (10 → 50) and `oxblock` (100 → 50).
  Nothing in the 2016 zone changes a character's level.
- **Replies**: `ac_wall` = `so_ply_Notice` (vt 0x784) → 0x2011 NC_ACT_NOTICE_CMD to the GM.
- **Log**: `AmpersandCommandLog` (`DebugLogging`), file `AmpersandCommandLog<YYYYMMDD><hh>.txt`, only for levels 1…100 (B1).
  `&debuglogging` switches every `DebugLogging` file (master switch `dl_ActivAll`), including this one.

## 2. Commands that change persistent state or reach other servers

Character DB: `&makeitem` (0x3401 via `sp_CreateItemByAdmin`), `&cleariv` (0x3459), `&getmoney` (0x3438), `&learnskill` /
`&learnpassive` / `&alllearnskill` (0x4801), `&unlearn` / `&unlearnpassive` (0x4825), `&wedding` (0x1091),
`&setpetinfo` (0xD401), `&kqreward` (0x5815), `&levelup` (character save via `ws_save2DB`). WM: `&levelup`
(0x1074 / 0x400E, and 0x6401 NC_ANNOUNCE_Z2W_CMD type 4 when the new level equals AnnounceData row 4's Value), `&releasechatban` (0x0866). Zone ring: `&pfind` / `&psummon` / `&kickout` (0x1068…0x106C),
`&expbonus` / `&itembonus` / `&fieldbonus` (0x1810 / 0x1811), `&zonelink` (0x0811), `&weddingreset` (0x2055).
GameLog: `&levelup` (0x041E), wedding-hall cancel (0x065F). Zone-local only (no WM message, see bugs): `&startGT`
(calls the WM-session start function locally), `&makeraid`, `&outraid`, `&inraid`.

## 3. Shared facts found on the way

- **Function profiler** `_PerformanceRecorder` (`FunctionProfiler::PerformanceRecorder`): the `pr_Entrance` / `pr_Exit`
  pair in nearly every function counts only while armed. `&performance n` (`pr_SetCount` FUN_00468180) arms it for the next
  n main-loop ticks (`pr_MainLoopHead` FUN_004678e0 / `pr_MainLoopTail` FUN_004681f0), then `pr_Report` FUN_004680d0
  writes `FunctionPerformance.txt` (function, exec count, total seconds, seconds per exec). Z11 §4.5.
  **Reading tip:** filtering `PerformanceRecorder` lines out of `clean.py` output also hides `pr_SetCount`; filter
  `pr_Entrance` / `pr_Exit` instead.
- `PerformanceChecker::pc_loopPERsecond` FUN_004cee50 (`performancechech`): main-loop rate = 32 / ((newest − oldest
  stamp of a 32-entry tick ring) / 10).
- `RandomBox::operator[](n)` FUN_00427c30 (`rndbox`) returns 0 for n outside 1…100 (Z11-B41 for the accessory-upgrade
  value; other callers with n > 100 would get the same constant).
- Accessory upgrade tables (`AccUpGradeDataBox`, `augdb_*` FUN_005c5a90…FUN_005c5c60): Z11 §4.3 and §9.3; Z04's upgrade
  handlers call the same functions.
- Raid iterator: 4 parties × 5 slots, `Raid::Begin` {0, 0}, `Raid::End` {4, 0} (Z11 §7.1). `CParty::PartyGetNo`
  FUN_00645160 scans all 4000 party slots.
- `ShineMobileObject::smo_IsActiveMode` FUN_0055d780: modes 1, 2, 4, 6 count as active (mask 0x56).
- `ShinePet::spt_FindMaster` FUN_00419a80: master must be non-empty, mode ∉ {0, 7}, on the pet's map.
- `ShinePlayer::so_GainFame` (vt 0x20, FUN_0042df00): fame += n while < 1,000,000 (capped), sends 0x2446
  NC_BAT_FAMEGAIN_CMD {u32 famegain}; level-up calls it with the new level.
- `FUN_0045d540` is `ShinePlayer::sp_MoverSystem_Type` *(pdb2016)*, not `GetRideKind` (fixed in `names/zone/Z11.json`).
- `&bigbang` / `&kingdomquest` / `cm_FindMapCluster` build whole temporary `FieldMap` / `MapCluster` objects (0xa028
  bytes for a cluster) as list search keys.

## 4. vtable slot method (used throughout Z11)

`rtti.vtables('Files/Server/2016/w00_Zone00/5ZoneServer2.exe')['ShineObjectClass::ShinePlayer'][slot // 4]` gives the
function address; its name comes from the `//==== FUNC <addr> <name>` headers of `re-data/exports/zone-pdb/decomp.c`.
The status file `docs/plan/status/Z11.md` lists every slot met (player, mob, NPC, mini-house, gamble object, inventory
lock list).
