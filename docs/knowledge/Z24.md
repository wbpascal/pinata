## Corrections to other docs

- Z04 l.1139 and Z02 l.790 call 0x132878f0 "g_ItemUseFunction": it is `useditemeffect` (pdb2016); the
  ItemUseFunction.txt holder is `itemusefunction` 0x0d67a1ec (§1.1).
- W05 §3.2 numbers the WM class mask from bit 0 = Fig. The WM's `ccdb_UseClassTypeToBit` FUN_00465a90 is the same
  code as the zone's: bit n = class ID n, so Fig = bit 1 … Sav = bit 27 (§7.1).
- Z09 §2.4 "charged buffs: rebuild p+0x2a5a0 …": the template DAT_132728f8 is `ShineObject::so_ChargedEffectContainerClear`
  (filled by `so_Initstaticvar` FUN_00549530); the per-slot work is `ciee_Routine` → `ciee_Activ` / `ciee_Free` (§6.7).
- Z12 §6.8 "el = ci_List.vt[8](ChargedBuffKey)": vt 8 is `List::l_AllocZ`; the list slot number *is* the buff's
  `ChargedBuffKey` (0x9002 / 0x9004 carry the slot, §6.7).

## Subsystem facts

- Stage order of the `useditemeffect` writers: wide → tough → sun → full → sleep → long; the last writer of an
  item's entry wins (§1.5 lists actor, skill and item set per writer; §6.6 the overlaps).
- None of these tables can be reloaded: `&reloaddata` (Z11 §8.6) only reruns `sdb_Load`, after which every
  `useskill` pointer of `useditemeffect` dangles (Z20 §7). §8 says what a second load call would do per table.
- Charged buffs: `ChargedEffectContainer` (p+0x2a5a0, 0x2e bytes) member ← `EffectEnum` map, template values and
  combine rule (max / sum with cap / assign) in §6.7; the use check `UseItemChargedBuff::uib_CanUseItem` returns
  0x700 / 0x712 / 0x713 with the same per-effect rules. EE_SETABSTATE (31) buffs are applied as abstates at login
  complete with the remaining time in ms (`ciee_AfterLoginComplete`).
- Time-limited items (own end date): `sp_ChargedItemLimitCheck` FUN_00451530 → `sp_ItemDelete` FUN_00451090 →
  `sp_DestroyItem` 00527870, skipped for a class-23 mount while the player rides (mode 6) (§6.7).
- Z04 §12.8 "color = item usage row value": 0x34B5 carries `EffectValue` (1 font / 2 balloon / 3 chat) at +0x16 and a
  uniformly random `ChatColor.shn` ID at +0x1a (`ccdb_GetChatColorIDByIndex(rb_largerandom(n))`, §7.7).
- `teib_CanUseItem(ext, term)` FUN_0064bbf0: the decompile shows the arguments swapped; the disassembly checks
  term ∈ list[ext] (§7.6). Only 2016 extend item: `TE_Arena_70` (312 Arena items). Only removable charged buffs
  (0x112E): the four `ExpHold*` items (§7.5).
- Production: `ItemProducer` (§7.8) fills 0x3457; inventory put-limit `ib_BagSizeInput(cec)` = 48 + 24·MoreInven
  (cap 192), take-limit `ib_BagSizeOutput` = 192; `ItemAttributeClass` vt 0x4 `iac_fill2buffer`, 0x1c `iac_GetLot`,
  0x20 `iac_SetLot`; lock list vt 0x30 `icl_ClearItem`. Codes 0xB01 ok, 0xB03, 0xB09, 0xB0A, 0xB0B (§7.8).
- `JustRevival`'s `ui_JustRevive` entry is overwritten by the ChargedEffect loader (Z24-B16, §1.5); the revive at death
  (0x302B `sp_NC_ITEM_REVIVEITEMUSE_CMD` FUN_00417580) does not use the table.
- MoverAbility WC/MA/AC/MR/TH/TB → the mover's `Item.Plus` in `Parameter::Container::c_StoreMover` FUN_0055e8d0 (§5.2).
- Class helpers (`ccdb_*`, §7.1): `CharClass` vt 0x48 = `cc_ClassType` (base class of the line: 1/6/11/16/21/26).
- Small shared helpers: `ItemDataBox::idb_2itemid` FUN_00418ff0 (BTree → u16, 0xffff none), `ItemDataBox::operator[]`
  FUN_00419020, `idb_GetItemInxName` FUN_006487d0, `idb_iter_next` / `idb_iter_Get` FUN_004900a0 / FUN_004900c0,
  `cWell512Random::well512_GetRandom(n)` FUN_0063cb10 = 0 … n−1, `AbState::as_FromIndex` FUN_00401420 (asserts idx > 0x317).
