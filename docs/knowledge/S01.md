# S01 knowledge: 2016 server PDBs (NA2016)

Facts other items need from the NA2016 set (`Files/Server/NA2016/`): the same 2016 builds as `Files/Server/2016/` plus
the private PDBs of Login, WorldManager, Zone, Account and AccountLog. Sections are added part by part (status:
`docs/plan/status/S01.md`). Evidence labels as in `AGENTS.md`; *(pdb2016)* = name or type from these PDBs.

## 1. NA2016 executables: private-server patches

### 1.1 What differs from the 2016 exes

Compared section by section with the 2016 exes (same PE timestamp, RSDS GUID/age, entry point, checksum field):

| Server | `.text` / `.rdata` / `.data` / `.rsrc` | Last section |
|---|---|---|
| Login, Account, AccountLog, Character, GameLog | identical | `.reloc` replaced by `.custom` (RWX `0xE0000040`, virtual 0x1024, raw 0x1200, **all zero**) |
| WorldManager | `.text`: 11 hook sites (§1.2) | `.custom` @ 0x00A30000: 0x130 bytes of hook code |
| Zone (Zone00–04, byte-identical) | `.text`: 2 hooks + 2 byte edits (§1.3) | `.custom` @ 0x1550F000: 0x46 bytes of hook code |

Header: only the last section header and `SizeOfImage` change. The relocation data directory still points at the old
`.reloc` RVA (now the zeroed `.custom`) and `DYNAMIC_BASE` stays set; the checksum field is not recomputed.
`.custom` lies at the same VA as the 2016 `.reloc`. To disassemble a patched exe, copy the 2016 exe, paste the NA
`.text` and the `.custom` raw bytes over `.text` / `.reloc`, and run `objdump -D --start-address=…` on the copy
(llvm-objdump rejects the NA file itself: "end of the file was unexpectedly encountered").

All hooks are `jmp <custom>` + `nop` padding over the original instructions; the hook re-executes the overwritten
instructions with an extra check and jumps back. None of the five PDBs changes (they describe the unpatched code).

**Consequence for evidence:** a capture or observation from an NA2016-based server shows the patched behaviour in the
handlers below, not the 2016 behaviour. Read the 2016 code (the `<bin>` / `<bin>-pdb` exports) for the spec.

### 1.5 Other NA2016 files

- `GamigoZR/GamigoZR.exe` (+ `install.bat`, service `_GamigoZR`): a .NET 4 Windows service "Gamigo_Zone_Response_Service"
  (2019, "For sending the correct boot response to the 2015/2016 Gamigo Zone. Love, xkl."). It is an `HttpListener` on
  `http://127.0.0.1:58492/`, the certification address the zone fetches its start script from (Z01 §1 `FetchStartScript`
  FUN_005b07a0, Z10). Its UTF-16 string heap holds the answer: the header `[10000][10][{( USA V.0.001 )}]` and 42 hex
  lines (40 × 65 + 2 × 15 characters, 2 680 hex digits). Owner **Z10**: this is a working replacement response for the
  2016 zone (order and concatenation of the lines need the IL; extract with
  `python3 -c "import re;b=open('Files/Server/NA2016/GamigoZR/GamigoZR.exe','rb').read();print([m.decode('utf-16le') for m in re.findall(rb'(?:[\x20-\x7e]\x00){4,}',b)])"`).
