# D05 knowledge: GameLog server

Facts other items need. Details: `docs/pseudocode/db/D05-gamelog.md`. Names: `tools/protocol-re/names/gamelog/D05.json`
(handlers `fc_NC_*` = opcode names; helpers ours) and `tools/protocol-re/names/zone/D05.json`. Layouts:
`docs/protocol/annotations/D05.json` (key `gamelog`; the 4th field of each entry = the `tGameLog` column it fills).

## For senders (zone Z*, WM W01, Character D02–D04)

- **Link:** the GameLog server is DataServer type **3** (`SERVER_INFO "PG_W00_GLDB", 3, 0, 0, 0, "0.0.0.0", 9511, 100, 100`:
  port 9511, at most 100 links). On accept it sends raw `{02 01 08}` = 0x0801 S2SCONNECTION_RDY; the peer must answer 0x0802
  with `server_to_id = 3` and `key = server_to_id + server_from_id` (D05 §5). Until then every log packet is ignored
  (CheckAlive) and the link is never timed out (D05-B9).
- **Heartbeat:** after 30 s without any received frame the server sends 0x0804 once; 180 s later without traffic it closes the
  link. It answers a peer's 0x0804 with raw `{02 05 08}` (0x0805).
- **Framing:** normal Shine frames, no cipher; a frame longer than 0x2000 bytes or with length ≤ 2 closes the link
  ("패킷 오류 확인"). No per-command length check: short packets store stale bytes (D05-B1).
- **Ordering:** up to min(10 × CPU + 1, 81) workers take packets from one global queue, each with its own SQL connection; rows
  of one sender can be inserted out of order. Nothing is answered except 0x0402 → 0x0403 (`nLogNo`).
- **`tGameLog.nType`** = the command number (`opcode & 0x3ff`) for almost every handler; item logs use 510–520; the
  DATA_TYPE_0…L commands take nType from the packet (2016 values: 926–933, 2000, 2020–2022, 2025, 2030, 2040; D05 §4.3).
  Exceptions: 0x0462 MONEY_CHANGE stores nType 0 and no character (D05-B6); 0x075C stores an all-zero row (D05-B8).
- **Layout mismatches** a rebuilt zone must keep in mind: 0x0452 ITEM_UPGRADE is read with a 0x2D-byte layout while the 2016
  zone sends 0x2B bytes (D05-B2); 0x0415 MOVE and 0x044F ITEM_CREATE store constant map names "NEED"/"RouN" (D05-B3/B4).
- **Zone side:** the zone's GameLog session pool is at `0x14d43958`; generic DATA_TYPE builders `Send_NC_LOG_GAME_DATA_TYPE_4/5/F/G`
  (FUN_006144a0 / FUN_006145c0 / FUN_006146a0 / FUN_006147f0), script entry points `cSendGameLogDataType_4/5` (D05 §4.4).

## NC_SYSLOG (dept 50) text log

Lines go to `C:/data/gamigo-dwh/current/<yyyymmddhh>_fiesta_Gamelog_World<n>.log` (hourly), format
`"<Mon> <d> <hh:mm:ss> <host> <UTC ISO time> GAMELOG GAMELOG - <msg>"` with an SD element `[fiesta@onson key="value" …]`
(D05 §6). If the directory cannot be opened the server does not start at all (D05 §7.1, D05-B10).

## For D01 (Account / AccountLog, same DataServer code)

- D05 §7 documents the whole shared framework (WinMain, service install/remove via `UPLOAD`/`REMOVE` arguments, start order,
  listener, IOCP, CPacket framing, heartbeat, close, IOBuffer pool, ODBC, DebugMessage/ShineLog/crash dump/AssertClass, scriptor);
  addresses differ per binary, behaviour is the same.
- 0x2802 OPTOOL_S2SCONNECT_LIST_ACK entries are `{u8 world, u8 zone, u8 server id, u32 SHINE_DATETIME}` in GameLog (as the 2017
  `SERVER_CONN_INFO`); D01 §2 lists `{type, world, zone}`: probably the same code, D01 to recheck.
- 0x2803 CLOSE_SERVER_REQ sets a flag nothing reads (D05-B7); the Account server's `DAT_00654bbc` is the same.

## Data

- `tGameLog` columns *(db-backup)*: `nLogNo` (identity), `nType, nCharNo, sMap varchar(16), nMapX, nMapY, nMapZ, nTargetCharNo,
  nTargetID, nItemKey bigint, nInt1, nInt2, nInt3, nBigint1 bigint`; procedure ↔ column table in D05 §1.2. `usp_Login_setChannel`
  has no source in any backup (D06). Failed inserts are only written to `GameLog_<yyyy-mm-dd>.txt` in the working directory.
- The server loads `ItemInfo.shn` at start and never reads it; it does not start without the file.
