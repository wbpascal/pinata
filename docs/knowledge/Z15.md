## 1. Quest data and script language

- `QuestData.shn` is **not** an SHN table: own format `{u16 VersionNo = 6, u16 NumOfQuest}` + records of `QUEST_DATA`
  (0x2A8) followed by three NUL-terminated scripts in file order Start, Doing, End (size fields at +0x294 Start, +0x296
  End, +0x298 Doing). 2016: 2306 quests, client file byte-identical. Global `gQuestData` (`CQuestData`, DAT_1328c0b0);
  lookup `QuestData_Find` FUN_00635ff0 = hash map by id. Row layout §1.2 (start/end conditions, actions, rewards).
- `QuestParser.txt` maps names to numbers for the script parser; a blank line in it stops the zone at start-up (Z15-B7).
- Script language (§2.5): one command per line (`SAY`, `IF`, `GOTO`, `:label`, `SET/ADD/SUB`, `ACCEPT`, `DONE`, `LINK`,
  `SCENARIO`, `CALLPS`, `CREATE_ITEM`, `DELETE_ITEM`, abstate commands …); variables `m_Var[]` (RESULT = var 0). The
  progress variable is spelled `PROGESS` (Z15-B4). The client has no parser; it only executes the 0x4401 commands sent.

## 2. Objects and offsets

- `ShinePlayer.sp_QuestDiary` at `p + 0x173e8` (vt 0x808 `so_ply_QuestDiary`) = `ShineQuestDiary` wrapping a
  `CQuestZone` (= `CQuest` 0xB4 + parser). `CQuestZone + 0xB8` `m_ScriptParser`, `+0xD0` `m_Var[0]` (RESULT), `+0x888`
  `m_QSC.Cmd`, `+0x88D` `m_QSC.Data`. `CQuest` members §4.1; `+0xA4` `m_QuestRestTime` (reset instants from 0x441C).
- Diary: unsorted array of 0x20-byte `PLAYER_QUEST_INFO` {u16 ID, u8 Status, `PLAYER_QUEST_DATA` 0x1D}, linear search.
  At most **40** quests in progress (`GetNumOfDoingQuest`, error 0xC0F). The zone refuses to start above 3000 quests in
  the data (`zs_start_sink` assert) and pools 1500 diary objects.
- `m_bWaitResult` (script waits for a DB / client answer): who sets / clears it is the table in §3.1.
- Reward flag `so_GetIsQuestRewardReq` / `so_SetIsQuestRewardReq` (ShinePlayer vt 0xAE0 / 0xAE4): 1 between 0x441A and
  0x441B; `QuestStart` (not Doing / End) refuses while it is 1 (§5.4).
- ShinePlayer vtable slots used by the quest code: 0x20 `so_GainFame`, 0x340 `so_GetWMSHandle`, 0x344 / 0x348 char /
  user regnum, 0x420 `so_GetCharacterTitle`, 0x434 / 0x438 / 0x43c current money / exp / fame, 0x464 quest-reward
  releaser, 0x7D4 `so_ply_GetInventoryLockList`, 0x808 `so_ply_QuestDiary`, 0x9E4 `sp_IsEthereal`, 0xAE0 / 0xAE4 above.
- `InventoryCellLockList` slots: 0x10 `icl_IsAnyLock`, 0x1c `icl_Apply_N_Free`, 0x28 `icl_Free`, 0x40 `icl_StoreItem`,
  0x48 `icl_StoreMoney`, 0x60 `icl_QuestReward`.
- Recovering vtable slots: `rtti.vtables('Files/Server/2016/w00_Zone00/5ZoneServer2.exe')` and the `//==== FUNC` names
  of `zone-pdb/decomp.c`. PDB names of tiny folded functions mislead (identical-code folding: e.g. vt 0x4d0 shows
  `so_GetKQTeamType`, which is `return 2`).

## 3. Flows other items touch

- **Quest DB requests** (to the Character server, D04 §1) carry the 6-byte `ref` and are answered with 0xB41 on success;
  0xB42 clear failed, 0xB43 store failed, 0xB46 give-up store failed. Every code 0xB41…0xB5A: §7; script errors
  0xC00…0xC10 (0x4401 `Cmd 0`): §3.10.
- **Rewards**: `QuestNext` DONE → `Send_NC_QUEST_DB_DONE_REQ` 0x441A FUN_005bbe60 reserves money / items in the inventory
  lock list (`icl_QuestReward`) and sends money, exp, fame, title element and item creates in one packet; 0x441B
  `Recv_NC_QUEST_DB_DONE_ACK` FUN_005bfb30 applies or frees the reservation (§5.2, §5.3). The 0x345B / 0x345C ITEMDB
  path is never used by the 2016 zone (§5.5).
- **Title**: the DONE answer calls `CT_QuestSuccess` and `CCharacterTitleZone::CheckNewTitle(40)` (title logic: Z18).
- **Mob kills**: `so_KilledBy` → `PartyManufacture::pm_QuestCheck` / `RaidTask::rt_QuestCheck` → `so_ply_QuestCheck` →
  `ShineQuestDiary::sqd_MobDead` → `CQuestZone::QuestPlayer_NPCMobKill`; only player killers are credited (§6.2).
- **Job change scenarios** (SCENARIO 8/11/12/13) request a job dungeon over the zone ring (`ZoneRingPacketFindJobDungeon
  ::zrpb_Request` FUN_005a8d30; ring transport and 0x441F: Z14). A refused request leaves the script hanging (Z15-B45).
- **GameLog**: accepting a quest sends 0xC80F NC_SYSLOG_CHAR_QUEST_STARTED from the SET_INFO answer (§4.7).
- **Character save**: the diary goes to the WM in the char-save blobs (`MakeStruct_*`, 0x4010 chunked) and to the client
  at map login as 0x103A / 0x103B / 0x10CE / 0x10D7 (§5.7).
