# Z21 knowledge: zone set items

Facts other items need. Details: `docs/pseudocode/zone/Z21-set-items.md` (§ numbers below).

## Three mechanisms (§1)

| # | What | 2016 status |
|---|---|---|
| A | `SetItem.shn` / `SetItemEffect.shn` → per-cast multipliers `setitemskilleffect` (= Z03's `g_SetEffect`, DAT_1325edb0, 17 × u32, base 1000) | **dead**: neither table is loaded by the zone; every multiplier is always 1000 (§3.2, §3.8, bug Z21-B1) |
| B | `SetEffect.shn` (set name, piece count → `ItemActionID`), join key `ItemInfo.SetItemIndex` char[32] @ ItemInfo+0x156 | live: set actions are ordinary item actions (observer key 0xFFFF) added / removed on equip, unequip, drop and login (§4) |
| C | `AbstateElementInObject::aeo_SetItemEffect` (`SetItemAbstateEffect`, 4 × {u16 code, u16 value}) | live: written by the caster's item actions (codes 1000 + `SkillEffectIncreaseType`), saved in `ABSTATEREADBLOCK.setitem[4]` and restored at login (§5) |

A rebuild that loads the original tables unchanged reproduces 2016 by **not** loading `SetItem.shn` / `SetItemEffect.shn`
(or keeping all `g_SetEffect` values at 1000).

## Corrections to done items

- **Z12 §2.5** says the set-item buffer of an abstate is filled "from the caster's set-item effects". That source
  (mechanism A, `aeo_SetItemEffectStore` FUN_00510670) stores nothing in 2016. The live writer is
  `ShineMobileObject::so_ItemActonAbstateApp` (vt 0x5d4, FUN_0055dea0): the caster's item actions of
  `SkillEffectIncreaseType` 4/6/8/9/10/12/13/14 stored as codes 1004…1014 (21 of them are set actions). The refit
  codes ≥ 1000 of Z12 §2.5 come from there (§5.3).
- **Z03 §5.6 part E** describes the empower keep-time bonus as a bonus to the state's success rate. The code
  (`ShineMobileObject::so_SkillEnchant` FUN_00431ca0, vt 0x5a0, §5.7) rolls the plain `sucrate` and adds
  `ActiveSkillInfo.nT2[empower.keeptime − 1]` to the keep time. It also adds the item-action rate
  `SEIT_KEEPTIME_RATE_INCREASE` and `PassiveBuffKeepTimeUPRate` (skill group 99).
- Z03's `g_ShelterItem` (DAT_0087c4d8) = `g_AbstateShelter` *(pdb2016)*; `g_ShelterDie` (DAT_0087c4c8) =
  `g_AbstateNeverShelter`. Revive by item: `UseItemJustReviveAtDead::uib_Effect` FUN_00418b60 →
  `so_ReviveByItem` FUN_00417850 = `sp_ReviveNow(p, 1000)`, then `ab_Recover` of both shelters. It frees only the
  NeverShelter entry (§5.6).
