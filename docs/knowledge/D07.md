## What D04 §12 / §9.3 / §6.4 should be read as now

- D04 §12 bullet 1 (0x986B stack choose / merge rule "summarised") is **closed** by D07 §2.3–§2.7 (per-situation table in §2.7).
  The 0xF99–0xF9E meanings of `usp_GuildAcademy_withdrawMoney` stay open (D07 §4).
- D04 §12 bullet 2 (ITEM_OPT bytes 0x0D–0x20 for class 4) is **closed** by D07 §3.1–§3.2: the record is the
  `GuildTournamentReward.shn` row without its first two columns, bytes 0x0D–0x20 are the five random options IO_Str / IO_Con /
  IO_Dex / IO_Int / IO_Men (u32 each, stored as u16) and apply to every class with an option block: Amulet 4, Weapon 5,
  Armor 6, Shield 7, Boot 8, Bracelet 38 (not only class 4).
- D04 §6.4 `ITEM_OPT { u8 nType, u32 nValue @1, u32 nMin @5, u32 nMax @9, … }`: read as `{ u8 RewardType, u32 Value1 @1,
  u32 Value2 @5, u32 Value3 @9, u32 IO_Str @0xD, IO_Con @0x11, IO_Dex @0x15, IO_Int @0x19, IO_Men @0x1D }` (0x21 bytes); "min/max"
  only for type 5 (division share bounds); for items Value2 = lot, Value3 = weapon upgrade level.
- D04 §9.3 "type 3 → reward item lot (low 16 + 16 bits of data)": the lot is one u32 (the low dword of the u64 data).
- D04 §9.3 "the attribute-class helpers FUN_0044ff60 / FUN_0044d340 build the option block": they **read** the stored storage
  record into an attribute (`ItemStruct_Read`, FUN_0044ff60 = identity getter of the container); new items get a fresh
  attribute from `ItemAttr_MakeWithLot` FUN_00468000 (D07 §1.2).
- D04 §9.3 "failures → Error 1099 (0x44B)": the split path can also answer 0x44A and 0x44D, a failed single move 0x18A1 (D07 §2.5).

## Facts for other items

- **Attribute class container** (Character server, global DAT_006ef2e8, built by FUN_0044f330): table at +0x9C indexed by
  ItemInfo `Class` (0…0x26); class 32 and unknown items use the base `ItemAttributeClass` (0 bytes). Vtable +4 Write
  (attr → wire), +8 Read, +0x28 class number. Per-class wire sizes: D07 §1.3 (Weapon 0x41 + 3n, Armor/Shield/Boot/Bracelet
  0xD + 3n, Amulet 0x26 + 3n, n = option byte >> 1; BindItem 1 + 10·count; ItemChest 1 + 8·(count & 0xF); KingdomQuestItem 0;
  SkillScroll / WeaponTitlaLicence / GBCoin 1 byte never written, D07-B14). Probably the same shared library in the zone
  (Z04 `g_ItemAttrCls`), not compared.
- `ItemList_ByStorage` FUN_00469f70 → `p_Item_GetListType` (no ORDER BY, READUNCOMMITTED): record order of every storage list
  (academy reward box 0, guild storage, …) is unspecified.
- Box 0 = academy reward storage, box 2 = reward inventory; `p_Item_GetStorageEmpty` has no slot limit *(db-backup)*, so
  moves into box 2 never fail for space.
- 0x986C `nWantItemCnt` / 0x9882 `nWant_ItemLot` = wanted lot − lot found (D07 §2.7); 0x9882 is also sent with item 0xFFFF
  lot 1 after cen-only rewards (D07-B5).
