# Z14 knowledge: instance dungeons (cluster manager), zone-ring storage packets, raid internals (facts for other items)

Pseudocode: [`docs/pseudocode/zone/Z14-instances.md`](../pseudocode/zone/Z14-instances.md). Layouts:
`docs/protocol/annotations/Z14.json` (19 packets). Names: all functions used already have PDB names (`names/zone/S01.json`);
`names/zone/Z14.json` is empty.

## 1. Facts other items need

- **Instance data** = table `InstanceDungeon` of `9Data/Shine/World/Field.txt` (row `FieldOption::InstanceDungeonInfo`,
  0x6f B; columns Argument, IDNo, ZoneNumber, MapIDClient, ScriptName, ModeIDLv, EntranceType, Guild, Individual,
  NeedQuest, NeedItem, Consume, LimitTime (minutes), MaxUseChr, CheckSum, Spacer → `NeedItemID`). Not an SHN.
  Z08's `IDInfo_Find` FUN_00484470 = `FieldContainer::fc_GetInstanceDungeonInfo`; `IDCondition` FUN_004624d0 =
  `fc_CanEnterIndun`; `ShinePlayer_GetPartyKey` FUN_005605f0 = `so_GetInsDunGeonInRegNoAndType` (vt 0xa8c).
- **Level table** `g_IndunLevelData` DAT_0d026c30 = `fieldleveldatabox` (`FieldLevelDataBox`, `FieldLvCondition.shn`:
  MapIndex, ModeIDLv, LvFrom +0x22, LvTo +0x24); used by every gate / field-entry level check, not only instances.
- **Map type**: `FieldAttr` +0x36 (`KingdomQuestMap` column) is `FIELD_MAP_TYPE` 0 normal, 1 KQ (also the job-change
  dungeons), 2 mini-house, **3 instance dungeon**, 4 tutorial (`RouT`). Z08's "type 3 = instance" is confirmed (pdb2016 + data).
- **Instances** are the sub-maps of a FieldList row (`UrgDragon00..09`); each registers in the cluster named after the row.
  An instance is owned while `InstanceMap.RegisterNumber != −1`; key `{Category, RegisterNumber}`.
- **Timers** (routine every 15 s): empty ≥ 20 s → WM 0xA401 + 5-min countdown; players back → 0xA403; countdown over →
  delete (also 0xA403). Time limit (LimitTime minutes, all 0 in 2016 data) → "DungeonTimeout" wall text, delete 5 s later.
- **Delete** (`mc_DeleteInstanceDungeon` FUN_00486710): 0xA403 to WM, `fm_KickAll`, drop film, clear objects, regnum −1.
- **Zone ring**: 0x7493 (guild storage withdraw) is **not forwarded** by the receiver (only the next zone hears it,
  Z14-B10); 0x9872 / 0x9874 / 0x9884 / 0x9885 / 0xA404 / 0x10B1 / 0x441F are forwarded until they return to the origin.
  The academy ring handlers update the zone's local copy of the storage; the guild-storage one does not.
- **Raid** on the zone: `RaidSystem` (500 `Raid` slots, same library as the WM, W02) is created lazily by
  `RaidTask::GetRaidSystem` FUN_005cdda0; the zone reuses the WM's raid number as slot index (`CreateRaid` FUN_0063d6f0).
  Status packets go only to members on the sender's map (`rt_Broadcast`). 0xB023 list length is 2 bytes short (Z14-B12);
  0xB026 list length uses the 0xB023 formula (Z14-B13).
- `sp_EscapeFromEmptyID` FUN_00440910 runs at every map login: a player on an instance map not owned by his group goes to
  Roumen.
- 13 bugs Z14-B1…B13 (table in Z14-instances §7). Z08-B5 effect: a vanished raid member is never ejected; Z08-B9: the
  level-select flag is cleared on the next map login.
