# X01 knowledge: integration facts for other items

X01's output is `docs/pseudocode/README.md`, the entry point of the specification. What other items need from it:

## Where to look

- **Before trusting an older document**, read README §5 (superseded statements, grouped by the older file) and §4.8
  (older names that mislead). Finished items are never edited; their corrections live there and in the knowledge files.
- **Bug register**: README §6. §6.1 is generated by `docs/plan/status/X01-register.py write` from every table row whose
  first cell is `<item>-B<n>` (all `docs/pseudocode/**/*.md` except README / FORMAT, `docs/knowledge/*.md`,
  `capture-validation.md` §8). Re-run it after adding bug rows; do not edit §6.1 by hand. Marks (Superseded / Narrowed /
  Extended) are the script's `SUPERSEDED` dict and README §5.9.
- **Open points**: README §7 (open items, cross-cutting gaps, one row per document); X02 should start its capture
  scenarios from §7.2 and §7.3.
- **Cross-server sequences**: README §3 (opcode, sender → receiver, receiving handler `@ FUN_` per process).

## Names files

`tools/protocol-re/names/<bin>/*.json` merge in file-name order, the later file wins. `S01.json` adds official names
only for addresses no item named, so older items' names stay in the generated docs; `docs/knowledge/S01-renames.tsv`
maps every one to the official name (README §4.6, §4.7).
