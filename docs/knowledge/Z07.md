# Z07 knowledge: character data, stats, wedding, mini-house, cards, mounts, pets (facts for other items)

Pseudocode: [`docs/pseudocode/zone/Z07-character.md`](../pseudocode/zone/Z07-character.md). Names:

## 1. Answers to open questions

- **Z01 §8 (CHAR_PARAMETER_DATA in 0x1802):** `so_fill_CHAR_PARAMETER_DATA` @ FUN_005a2e00 fills the 2017 PDB struct
  `CHAR_PARAMETER_DATA` (0xE8 bytes, size confirmed). Each `SHINE_CHAR_STATVAR {base, change}` = stat matrix layer 0 and
  layer 15 (`p+0xfc0` / `p+0x1bb4`). Matrix stats 0–14 = STR, END, DEX, INT, SPR, WC min, WC max, AC, TH, TB, MA min,
  MA max, MR, MH, MB. `Wizdom` is not written. Prev/NextExp from `g_LevelExp[level]` / `[level+1]` (u64 table).
- **Player character block:** `p+0x7f3d` is a copy of `PROTO_NC_CHAR_BASE_CMD` (WM 0x101F): chrregnum, charid +0x7f41,
  Level +0x7f56, Experience +0x7f57, CurHP +0x7f67, Cen +0x7f77, LoginLocation +0x7f7f, `CHARSTATDISTSTR` +0x7f94
  (STR, END, DEX, INT, SPR spent points, RedistributePoint +0x7f99), prisonmin +0x7f9f, adminlevel +0x7fa1.
- **Z02 §8 production:** the 2016 client's `ProductTask` (client FUN_004872f0) **sends 0x2035 and 0x2039**; the path is live.
  When the cast ends, `ShineMobileObject_so_Routine` (FUN_0056a080) calls `smo_ply_ItemProduce` (vt 0xecc, FUN_0046c2d0) →
  DB `0x3457`. Only the server's result/broadcast packets (0x2036/0x2038/0x203A/0x203B/0x203C) are ignored by the 2016 client;
  it sees the result via item changes and `0x481D NC_SKILL_SKILLEXP_CLIENT_CMD`. Z02-B5 should be narrowed accordingly.
- **Z02 §10 wedding:** `Partner.RegisterNumber` (`p+0x5ced`) is written only from the Character DB (`so_ply_WeddingData`
  FUN_005a20d0, `so_ply_WeddingInfoUpdate` FUN_0059f390). 0x1095 is a zone-ring partner lookup for 0x1093 (partner info),
  not part of proposing. DB answers 0x1084…0x1092 only re-request `0x1080 WEDDINGDATA_REQ` for the local player(s) and
  ring-refresh the partner; 0x108A/0x108C also send `0x205D {0x1380}`; 0x1092 gives the couple item DAT_14d504be and two
  skills (0x4801). Status (inferred): Main 0 single, 1 engaged, 2 married, 3 divorced; Sub 1/2 divorce by agreement (self /
  partner), 3/4 forced (self / partner). On a married login the zone sets abstate 293 StaWeddingBuff.
- **Z04 §6 mount/pet:** mount riding = `so_MoverSystem_GetOn` / `GetOff` (FUN_0045d7a0 / FUN_0045f020); the mount recovery
  tick is `p+0x29634` = FUN_0056b5f0 with interval/‰ from `g_MoverUpgrade[grade]`.

## 3. Shared mechanisms

- WM login blobs (0x101F…0x1130) all dispatch to one ShinePlayer slot each; table in Z07 §1.2. A bad ref on most of them
  disconnects the player with reason 0x689.
- Mini-house edit requests share the `InHouseOwner` check (codes 0x1193 / 0x1184 / 0x1187 / 0x1188) and broadcast the change
  to the house map with `so_AllInMap1(p, list, 1)`.
- Furniture/portal effects with a cost lock items/money and go to DB 0x347D / 0x3489 (answers are Z05).
- Card registration locks the card cell with an `InvenCellReleaser_CardRegist`; DB answer 0xC40A commits (0x2B90) or releases.
