# Z23 knowledge: per-player active skill list

Facts other items need. Full pseudocode: `docs/pseudocode/zone/Z23-skill-list.md` (§ numbers below).

## Structures (pdb2016)

- `ShinePlayer::sp_SkillList` = `CharaterSkillList` at player **+0x17d08** (0x24 bytes): `csl_Skill`
  `std::vector<CharSkill>` (0x14 each: +0 u16 id, +4 `cs_EndOfCooltime` (g_Now tenths), +8 `SKILL_EMPOWER` u16,
  +0xc `cs_Mastery` u32, +0x10 `cs_bSave`), **sorted by ID**, looked up with `_Lower_bound`; +0x10 `csl_SkillNumber`;
  +0x14 `csl_ToggleSkill` vector of `{u16 id, u8 cts_bSkillOn}`. Every learned step of a line is its own entry. §1.1.
- `SKILL_EMPOWER`: four 4-bit fields damage / sp / keeptime / cooltime (bits 0–3, 4–7, 8–11, 12–15); the limit (5 per
  field) is per line (sum over learned steps), the points are stored on the step named in the request. ActiveSkill
  empower columns are read as `nTk[points − 1]` (k = 0 damage, 1 sp, 2 keeptime, 3 cooltime). §4.
- `ShineMover::smv_MoverSkillList` = `MoverSkillList` at mover **+0x1f54**: vector of `{u16 id, u32 end}`;
  `MoverUseSkill.shn` has 0 rows in 2016, so mount skill lists are always empty. §1.2, §9.1.

## Rules

- Cooldown end = `g_Now + ms·10/1000 − 3` (g_Now in tenths of a second); the DB save stores seconds. Delay group:
  casting a skill with `DlyGroupNum` g sets every learned skill of group g to `DlyTimeGroup` (group 0 included:
  Z23-B3). 0x4821 NC_SKILL_COOLTIME_CMD carries seconds. §3.
- Toggle skills (only BurnPain01–06 in 2016): a cast switches on (no cooldown) or off (full cooldown); 0x245C / 0x245D
  `{u16 nSkillID}` to the player only; the client starts its cooldown display on every 0x245D. Automatic switch-off on
  link, tent, mount, condition loss. Their states (`StaBurnPainMe` / `StaBurnPainFoe`) have `AbStateSaveType 0`: never
  saved on link or logout (`AbnormalStateSaver::lid_Call` FUN_00454b10 tests `IsSaveLink` / `IsSaveLogoff`). §2.
- SP before each blast pass: `smo_SPCheck` (vt 0xedc; player = `csl_SPCheck` test only, skipped while `InSkillShift`;
  mover always true); paid after the blast by `smo_SPCheckConsume` (vt 0xee0, Z03 §5.4). §4.
- Unlearn removes exactly one step (not the lower ones) and leaves its toggle entry (Z23-B11). §6.4.
- Mastery gain is applied when the produce request is sent, before the DB answers; 0x481D `{u16 skill, u32 mastery}`
  is handled only by the client's `ProductTask`. §5.

## Utilities

- `RandomBox` (global `rndbox`, FUN_0063cdb0): box n = 1…100 is a shuffled ring of 16384 values uniform over 0…n−1;
  `rndbox[n]` (FUN_00427c30) returns the next one, 0 for n outside 1…100. §11.
- Charged stat / skill-empower reset request: `UseItemStatClear::uib_DirectUse` FUN_00599990 →
  `sp_StatEmpowInitialize` FUN_005183f0 sends GameDB 0x9005 / 0x9006 (lot − 1 or delete); answers Z08 §11. §4.
