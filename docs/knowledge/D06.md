## Corrections

Corrections to D01–D05 statements (their files are not edited; X01 picks these up).

- **D01 §3.4 / §7, 0x0C26 TEENAGER nType 1:** the minute value is `(int)(17940 − elapsed) / 60` = minutes until the
  17 940 s window after the last logout ends (asm @ 0x4029c6: `fsubrp` with 17940.0 on top of the stack, then `ftol`
  and `/ 60`). D01's guess is confirmed; no longer inferred.
- **D01-B4 (TW login fails):** holds against the NA database only. The official wrapper name of the 5-parameter
  `usp_User_LoginGame` call is `CSQLPAccount::usp_UserTWLoginGame` (pdb2016); one SQL Server database cannot hold it next
  to the 6-parameter `usp_User_loginGame` (names are case-insensitive), so the Taiwan service had its own Account
  database with its own procedure (D06 §2.4). The 2016 NA client never starts the TW path.
- **D01 §3.4 teen protection:** `p_UserKey_Get_FromAccount` writes the user key into a 25-byte output buffer (struct
  field `sUserKey[50]`): keys are at most 24 characters.

- **D01-B10 (0x082C EVENT_L20):** the first half is wrong. Both L20 wrappers set `nRet = −1` before binding
  (`p_Event_L20_Get` @ FUN_00415360, asm `mov dword [edi+0x20], 0xffffffff` @ 0x41538e; `p_Event_L20_Set` @ FUN_00415450
  the same), so after an SQL error the branch is deterministic: Get error → nError 0x128a. Only the log-condition half
  (`nRet ∉ {1,3}`) stands, and it is intended: 1 = already rewarded, 3 = event over are expected refusals (D06 §3.3).
- **D01 §4.2 L20 codes:** Get `nRet` > 0 = already rewarded (0x1289), −1 = error (0x128a), 0 = not yet → Set; Set `nRet`
  0 = granted (0x1288), 1 / 3 / other → 0x128b (D06 §3.2–§3.3, inferred from `p_Event_WorldCup_Enter`'s codes).
- **D01 §4.5 / knowledge D01 "client-version":** `spawnapps` is not a version. The 2016 client sets it to `"Original"`
  and overwrites it with the first entry of `Fiesta.ini` (@ FUN_0045b1b0, "SpawnApps Off." for "Original";
  sent by `AccountFrameWork::NcUserLoginReq` @ FUN_0046f0a0): a launcher / partner-portal tag. GameLog's
  `usp_Login_setChannel` stores it as the login channel (D05 §2.2's guess confirmed, D06 §4.1).
- **D05 §1.2 / §9 Type6 version:** for a rebuild, follow `w00_GameLog.bak` (plain insert): it is the only GameLog backup
  with every procedure the 2016 binary calls (`p_GameLog_Add_TypeL`) and the database `ServerInfo.txt` names. What the
  live 2016 database had stays open (D06 §4.2).
- **D01 §4.4 `usp_AccountLog_GetDateDiffLastlogout`:** inferred body `SELECT TOP 1 DATEDIFF(s, dDate, getdate()) FROM
  tAccountLog WHERE nUserNo = @nUserNo AND nType = 2 ORDER BY dDate DESC` (D06 §3.4); the wrapper's `nRet == 0` test is
  a dead check with the SQL Server drivers (D06-B1), the same applies to D01 §3.3's `usp_ReturnUser_GetDatediffLastlog` and `usp_User_GetDatediffCreated` wrappers (result set + `@nRet`).

## For a rebuild (Account DB)

- Of the eight Account procedures without source only `usp_Pcbang_chkIP` is on a live 2016 path (WM 0x082F at every zone
  login). Answering `@nRet = 0` always is a faithful "no PC-bang" implementation; 1 adds +200 to the zone's map drop
  rate (Z09). The others serve the KR Netmarble, TW, JP logins, KR teen protection and the HIT3 cash event, which no 2016
  binary triggers.
- No wrapper in the four DB binaries binds a procedure `RETURN` value (`{? = CALL …}` never occurs): only output
  parameters and result sets reach the servers.

## For a rebuild (AccountLog / Statistics / GameLog)

- Live in 2016: `p_SameTimeCharClass_Add` (Statistics DB, WM 0x080A) and `usp_AccountLog_GetDateDiffLastlogout`
  (WM 0x0C62); GameLog `usp_Login_setChannel` (every character login, result ignored). `p_Event_L20_Get/Set` serve the

- All AccountLog / Statistics procedures that have source match the 2016 binds (D06 §3.5); take them from the backups.
- Driver rules for every procedure (D06 §1.2): output parameters of a procedure that also returns a result set are not
  visible to a wrapper that tests them before fetching; never return NULL in an output parameter (SQLSTATE 22002).
