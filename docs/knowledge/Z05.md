# Z05 knowledge: ITEMDB protocol, how item changes are committed (facts for other items)

Pseudocode: [`docs/pseudocode/zone/Z05-itemdb.md`](../pseudocode/zone/Z05-itemdb.md). Names: `tools/protocol-re/names/zone/Z05.json` (23).
Layouts: `docs/protocol/annotations/Z05.json` (38: DB→zone answers and the client packets they produce).

## 1. Commit model (for D03, Z06, Z07, Z13, X01)

- **Style 1 (almost all):** request reserves cells/money under a per-player 16-bit *lock index* (`InventoryCellLockList` at
  `p+0xfaa8`, index `p+0xfaac`), DB answer carries the index back. Success → `L.vt[0x1c]` `icl_Apply_N_Free` (FUN_0048be90) runs each
  reservation's `InvenCellReleaser_*::icr_Apply` (table in Z05 §1.4) which writes memory and sends `0x3001`/`0x3002`/`0x1033`.
  Failure → `L.vt[0x28]` `icl_Free` (FUN_0048b2c0): reservations dropped, memory never touched. `L.vt[0x20]` (FUN_0048c100) = apply
  with a corruption check that disconnects with `0x690` (used by `USE_ACK`).
- **Style 2 (drop, pick-up, pick money, INC_DEC_MONEY):** memory changed first, `L+0x7828` "DB pending" flag set (`L.vt[0x14](1)`);
  the flag makes `L.vt[0x10]`/`vt[0x18]` report busy. Success clears it; failure → `so_Disconnect(0x684)` (no rollback, relog reloads).
- Lot consistency after merge/split: zone lot ≠ DB result lot → `so_Disconnect(0x68c)`.
- Answers for a closing player / charNo mismatch are ignored without freeing (the lock list dies with the object).
- No timeouts: a lost answer blocks the player's item operations until relog.

## 2. Answer layouts (for D03)

All answers start with `ref {u16 objHandle, u32 charNo}` except `MOVER_*`, `ITEMMONEY_BUY`, `RANDOMOPTION_*`, `TERMEXTEND`
(`{u16 lock, u32 charNo, u16 handle, u16 err}`), `CLASS_CHANGE`, `MIX_ITEM` (`{u32 charNo, u16 handle, u16 lock, u16 err}`),
`ITEMINFO`/`ITEMREBUILD` (`{u32 charNo, u16 handle, …}`), `CHAT_COLOR_CHANGE` (`{u16 err, u16 lock, u32 charNo, …}`, looked up by charNo),
`REPURCHASE_*` (`{u16 handle, u32 charNo, u16 err, u16 lock}`). The PDB structs match after the ref prefix. Generic FAIL answers are
`{ref, u16 error, u16 lockindex}`.

**Success codes the zone tests** (anything else = failure): USE 0x700, UPGRADE 0x8c3–0x8c7, NEW_UPGRADE 0x3803–0x3805, BRACELET 0x3c07–0x3c0b,
DEPOSIT/WITHDRAW 0xf80, GUILD_STORAGE_WITHDRAW 0x1480, academy withdraw 0x17e0 / deposit 0x19a0, CHARGED 0x1041, ITEMCHANGE 0x901,
PRODUCE 0xb01, DESTROY 0xb81, QUESTREWARD 0xbc1, DISMANTLE 0x1680, MINIHOUSE_EFFECT 0x1700, FURNITURE_ENDURE 0x700, WEAPON/SHIELD
ENDURE 0x1a80, ENCHANT 0x2080/0x2090/0x20a0, MYSTERY_VAULT 0x2140, GETFROMCAPSULE 0x2840, BELONGED_CANCEL 0x2880, ITEMINFO 0x2b00,
ITEMREBUILD 0x2b40, BOOTHTRADE 0xa41, MOVER 0x3230 / RAREMOVER 0x3238, ITEMMONEY_BUY 0x3240, RANDOMOPTION 0x3248, RECOVER 0x3251,
CHAT_COLOR 0x3600, TERMEXTEND 0x3618, REPURCHASE 0x3668, CLASS_CHANGE 0x3680, FRIEND_POINT 0x36c0, MAPLINK 0x3748, MIX 0x37c0,
BUYCAPSULE 0x201.

## 3. Facts for other items

- **D03 / Z07:** `0x3489 MINIHOUSE_PORTAL_EFFECT_DEMANDGOOD_REQ` has no Character-server handler and the zone has no `0x348A` handler
  (Z05-B12): paid portal effects hang.
- **D03:** the Character server sends `0x3415`/`0x3481` as `{ref, err 0x28a, lock}`; the zone reads the lock at the err offset (Z05-B5).
- **Z07 / Z13:** upgrade outcomes feed the pet mind/stress (`ShinePlayer_PetReaction` FUN_004d2470, only with a pet out) and the
  character-title counters (`vt 0x420` block, conditions 0x1b–0x20); mystery-bolt boxes: `sp_MysteryVaultMakeItem` FUN_005658f0
  (MysteryVaultServer.shn) → `0x349E`.
- **Z02:** `ReactionType.shn` (`g_ReactionType`): after a purchase from NPC `LC_Machine` the zone sends `0x2072` (NPC animation).
- **Z04:** `p+0x2ab18` = auto-arrange running; every failed move/merge answer aborts the auto-arrange.
- **Z06:** the Character server answers each trade partner separately; `0x343D`/`0x343C` close the trade menu (`so_CloseTradeMenu` FUN_005924c0, fail → `0x4C23`); `0x3456` booth trade applies both
  sides' locks and edits the seller's booth for SELL types 4/5/6 (BOOTH_TRADE_TYPE), fail → buyer `0x680E`.
- **Z07:** production result `0x3458` → `0x203B`/`0x203C` (ignored by the 2016 client); mini-house effect `0x347E` →
  `so_MH_EffectApply` or `0x8C41` with 0x16D0–0x16D5; mushroom `0x3468` → `MiniHouseStr_mhs_Init`; class change success schedules a
  logout 30 s later (`sp_Schedule_Logout`).
- **Z08:** `0x345C` → `CQuestZone_Recv_NC_ITEMDB_QUESTREWARD_ACK` (FUN_005bf7f0); friend point `0x34C0` → `0x5422`, plus WM `0x5423`
  when the item is `FriendBroadcastItemID`. Every upgrade completion calls `QuestPlayer_ScenarioDone_Server(q, 5)`.
- **W03:** guild-token purchases send `0x74C0 NC_GUILD_ZONE_USE_GUILD_TOKEN_CMD {guildNo, price, 0}` to the WM on every success answer,
  even if the buyer is gone. Guild storage withdraw → `0x7493` to the other zones.
- **Z04:** success ACKs are `0x3004 {0x201}` (buy, soul stone, capsule), `0x3005 {0x381}`, `0x3008 {0x301}`, `0x300A {0x341}`,
  `0x300C {0x241}`, `0x300E {0x441}`, `0x3011 {0x281}` for equip **and** unequip (the unequip success goes out as EQUIP_ACK; the
  client's UNEQUIP success code `0x2c1` is never sent, Z05-B2), `0x3016 {0x700}`, `0x301D`/`0x301F {u64 cen, 0xf80}`.
  Soul-stone purchases: the PointStone releaser sends `0x5003`/`0x5004 {new total}`, then `0x3004 {0x201}`.
  The ENDURE answers are handled by the ShinePlayer overrides FUN_0051a260/FUN_0051a870 (the ShineObject base versions are empty).
- Releaser `ItemSell` adds the sold item to the repurchase list (`0x305C`), `ItemRepurchase` removes it (`0x305D`).
